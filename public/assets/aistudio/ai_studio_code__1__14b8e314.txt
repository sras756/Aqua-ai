# AQUA AI — FINAL MASTER IMPLEMENTATION SPECIFICATION (ENHANCED)
**Role:** Principal Android Architect & Production AI Systems Engineer  
**Target Platform:** Android (Native)  
**Objective:** Evolve the existing Aqua AI repository into a production-ready, voice-first, supervised autonomous personal AI assistant powered by Google Gemini, integrating native Android device control, Google Drive cloud synchronization, persistent memory, an isolated web browser, and a non-custodial multichain cryptocurrency wallet.

---

## 0. EXECUTION MANDATE & NON-NEGOTIABLE ENGINEERING RULES

1. **Zero Mockups / Zero Stubs:** Every module, UI screen, tool integration, and API call must be genuinely implemented and wired end-to-end. Do not simulate success, hardcode fake responses, or mark any requirement complete until its implementation and acceptance tests pass.
2. **Preserve & Migrate First:** Do not discard working features, design tokens, or existing flows. Inspect the entire repository first and refactor/extend incrementally.
3. **Offline-First Single Source of Truth (SSOT):** Local encrypted storage (Room + SQLCipher) is always the primary operational source of truth; Google Drive acts as the synchronized cloud store and backup destination.
4. **Zero-Trust AI & Security Boundary:** Never grant the LLM direct access to OS shell execution, raw OAuth tokens, private keys, seed phrases, or unverified financial signing. All external data (webpages, emails, notifications, files) must be treated strictly as **untrusted data**, never as executable system instructions.
5. **Phase-Gated Execution:** Execute strictly phase-by-phase. At the end of each phase, run builds, static checks, and automated tests before proceeding to the next phase.

## 3. GEMINI INTELLIGENCE ENGINE (`core:ai`)

Implement a centralized, model-agnostic-interface Gemini service supporting:

### Capabilities
- **Streaming & Real-Time Multimodal Interaction:** Token-by-token text streaming (`Flow`) and bidirectional audio/live streaming support for natural voice conversations.
- **Multilingual Intelligence:** Context-aware comprehension and generation in **English** and **Urdu** (including Roman Urdu / Nastaliq / mixed-code conversational handling) plus additional supported locales.
- **Structured Output & Function Calling:** Strict JSON-schema-validated structured outputs and a typed **Tool Registry** exposing only approved Aqua service tools.
- **Task Planning & Recovery:** Separate **Planning** calls from **Tool Execution** loops; support automatic retry with exponential backoff, context-window compaction/summarization, rate-limit handling, and graceful offline/API-failure fallbacks.
- **Observability & Configuration:** Model selector/routing (e.g., fast Flash-tier for voice/routing, Pro-tier for deep reasoning/planning), configurable temperature/safety/system prompts, and persistent token & usage metering per session/task.

### Security Requirements
- **Zero Embedded Secrets:** Never embed raw Gemini API keys in `BuildConfig`, XML resources, assets, or APK binaries. Route calls through a secure backend proxy or managed client-attestation infrastructure (e.g., Firebase AI Logic + Firebase App Check).
- **Controlled Tool Interface:** Every Gemini tool call must pass schema validation and be intercepted by the **Aqua Agent Authorization Gate** before execution.

## 4. AQUA VOICE ENGINE (`core:voice`)

Implement a low-latency, voice-first pipeline supporting:

- **Speech-to-Text (STT) & Text-to-Speech (TTS):** Support real-time streaming speech recognition and natural spoken responses with configurable voice speed/pitch.
- **Multilingual Auto-Detection:** Seamless switching and recognition for **English** and **Urdu**, accurately rendering spoken summaries and command transcriptions.
- **Voice Interruption (Barge-In):** Immediately halt TTS playback and capture user speech when the user interrupts mid-response.
- **Listening Modes:**
  - Push-to-talk / tap-to-speak.
  - Continuous conversation mode during explicitly activated sessions.
  - Optional opt-in wake-word detection (battery-conscious and clearly toggleable).
  - Background voice operation only where permitted by Android OS policies, running as a compliant **Foreground Service** (`foregroundServiceType="microphone"`).
- **Safety & UX Controls:**
  - Runtime `RECORD_AUDIO` permission flow with clear rationale and degraded text-only fallback if denied.
  - Persistent, unmistakable listening indicator and Foreground Service notification with an **immediate one-tap Stop-Listening / Mute control**.
  - Proper `AudioManager` audio-focus negotiation (ducking/pausing media during interaction and restoring cleanly).

## 6. GOOGLE DRIVE CLOUD STORAGE & SYNC ENGINE (`core:drive`)

Google Drive is the primary cloud storage and backup destination.

### Authentication & Scopes
- Implement OAuth 2.0 using modern Android standards (**Credential Manager + `AuthorizationClient`** or **AppAuth-Android with PKCE**).
- Request **minimum necessary Drive API scopes** (e.g., `drive.file` for app-created/user-authorized workspace folders; avoid broad full-drive read/write scopes unless explicitly opted into by the user for File Manager features).

### Mandatory Google Drive Folder Structure
Create and maintain a root `Aqua AI/` directory containing isolated subfolders:
1. `Account data/`
2. `Conversations/`
3. `Memory/`
4. `AI documents/`
5. `Research/`
6. `Browser bookmarks/`
7. `Task history/`
8. `Automation records/`
9. `Backups/`
10. `Exports/`

### Synchronization Engine Requirements
- **Room-First + WorkManager:** Write all changes locally to encrypted Room first, enqueue sync mutations in an **Offline Change Queue**, and process via `WorkManager` (`NetworkType.CONNECTED`) for automatic and manual sync.
- **Conflict Detection & Versioning:** Track Drive `fileId`, `modifiedTime`, `version`/ETag, and local SHA-256 content hashes. Detect concurrent edits, preserve conflict copies or prompt resolution, and handle retries with exponential backoff.
- **Search, Retrieval & Restore:** Support full metadata/content search across synced documents and one-tap **Backup Restoration** into Room.
- **Sync Telemetry UI:** Real-time sync state indicators (`Synced`, `Syncing`, `Pending Offline`, `Conflict`, `Error`).
- **Strict Secret Exclusion Filter (Non-Negotiable):** Enforce an automated pre-upload sanitization filter that **blocks** wallet mnemonics, private keys, keystore blobs, OAuth tokens, raw device identifiers, or unencrypted credentials from ever entering the Drive sync queue.

## 8. AQUA BROWSER (`feature:browser`)

Build a dedicated, security-hardened Android browser (WebView / GeckoView / equivalent Android-compatible engine) deeply integrated with Aqua's research capabilities:

### Core & AI Browser Features
- **Standard Browser Controls:** Omnibox (URL + search suggestions), multi-tab management, bookmarks (synced to Drive), history, download manager (with Security Guardian scan), and **Private/Incognito tabs** (isolated cookie/storage profile, zero history/memory persistence).
- **Reading & Intelligence:** Reader mode (clean DOM extraction), inline page translation (including English <-> Urdu), AI webpage summarization, multi-tab comparison, **Research Mode** with verifiable source citations/links, and structured content extraction.

### Security & Prompt-Injection Firewall
- **WebView Hardening:** Enable Safe Browsing, block `file://` and `content://` access (`allowFileAccess = false`, `allowContentAccess = false`), enforce HTTPS/block mixed content, isolate site cookies/storage, and restrict JS interfaces strictly to sanitized, read-only extraction scripts.
- **Prompt-Injection Defense:** Extracted DOM text, metadata, and URLs must be wrapped in strict untrusted-data delimiters when passed to Gemini. **No webpage content may alter system instructions, forge approvals, or invoke Aqua tools directly.**

### Dual Workspace Access Modes
1. **USER VIEW:** Clean, read-only presentation of AI-generated reports, summaries, and workspace artifacts. Prevents accidental corruption of AI-structured records while allowing user annotation/export/deletion.
2. **AI WORKSPACE:** Authorized read/write sandbox where the Aqua Agent creates research reports, synthesizes cross-source findings, updates working notes, and organizes files (persisted locally and synced to `Aqua AI/Research/` and `AI documents/`).
- **Data Ownership:** Users retain full ownership to export or permanently delete any workspace content at any time.

## 9. AQUA NATIVE MULTICHAIN WALLET (`feature:wallet`)

Develop a modular, non-custodial, zero-trust cryptocurrency wallet engine.

### Blockchain Architecture
Define a clean `ChainAdapter` interface with production implementations for:
- **Bitcoin** (BIP-44/49/84/86, UTXO management, fee rate estimation)
- **Ethereum** (EIP-155, ERC-20, EIP-1559 gas estimation)
- **Polygon** (EVM adapter)
- **BNB Smart Chain** (EVM adapter)
- **Solana** (Ed25519 / SPL tokens, priority fee & blockhash handling)
- **Extensible Registry:** Plug-and-play support for additional EVM/non-EVM chains.

### Wallet Capabilities
- Create new HD wallet (BIP-39 mnemonic generation via `SecureRandom`), import existing wallet, derive addresses, and verify recovery backup.
- Real-time native & token balances, transaction history, QR code scanner/generator (EIP-681 / BIP-21 / Solana Pay), network switcher, dynamic fee estimates, transaction status tracking, and supported dApp connection (e.g., WalletConnect v2 with domain verification).

### Cryptographic & Signing Security (Critical)
- **Audited Cryptography Only:** Use vetted open-source cryptographic libraries for BIP-39/BIP-32/secp256k1/Ed25519; never implement custom cryptographic primitives.
- **Hardware-Backed Key Storage:** Encrypt seeds and private keys using a Data Encryption Key wrapped by **Android Keystore** (StrongBox where available). Exclude all wallet databases and preferences from `android:allowBackup` and Drive sync.
- **Biometric & PIN Gating:** Require `BiometricPrompt` (or strong device/wallet PIN fallback) to reveal recovery phrases or authorize transaction signing. Apply `WindowManager.LayoutParams.FLAG_SECURE` on all sensitive wallet/seed screens.
- **Transaction Validation & Simulation:** Verify destination address checksums, warn on suspicious/unverified contracts or approvals via Security Guardian, and display human-readable transaction simulation/fee breakdowns before signing.
- **Strict AI Air-Gap:** Gemini may query *public* blockchain data, explain transactions, and construct *unsigned* transaction drafts. **Gemini must never read private keys, access decrypted keystores, or trigger silent transaction signing.** Signing requires explicit user review and independent native confirmation.

## 10. SUPERVISED AUTONOMOUS AGENT ENGINE (`core:agent`)

Implement the central orchestration engine governing all multi-step tasks.

### Formal Task State Machine
Every task must transition deterministically through:
`CREATED -> PLANNING -> AWAITING_APPROVAL -> EXECUTING -> VERIFYING -> COMPLETED | FAILED | CANCELLED | ROLLED_BACK`

1. **Receive Instruction** (Voice, Chat, Automation trigger, or Share intent)
2. **Understand Objective & Gather Authorized Context** (Memory, Drive, Screen, Web)
3. **Generate Structured Execution Plan** (Ordered steps, required tools, risk classification)
4. **Check Permissions & Risk Tier**
5. **Request Explicit User Approval** (if Risk Tier >= 2)
6. **Execute Authorized Tool Actions** (with progress streaming & cancellation checks)
7. **Verify Outcome** (post-condition check; trigger retry or error recovery on failure)
8. **Persist Immutable Audit Log & Task History**
9. **Report Concise Outcome** (UI + optional spoken summary)

### Risk Classification & Supervision Matrix
- **Tier 0 (Auto-Execute):** Read-only queries, local search, summarization, web search within approved permissions.
- **Tier 1 (Workspace-Scoped):** Creating/updating notes or AI Workspace documents, bookmarking.
- **Tier 2 (Explicit Confirmation Required):** Sending communications, modifying/deleting user files, controlling device UI/settings, changing calendar/contacts.
- **Tier 3 (Explicit Confirmation + Biometric/Strong Auth):** Financial transaction signing, granting sensitive OS/OAuth scopes, exporting sensitive data, bulk deletions.

### Agent Controls
- Concurrent/queued task manager with live step-by-step progress UI.
- Instant **Pause / Cancel** button for active tasks.
- Automatic failure recovery, retry limits, and immutable local audit logs (`AuditLogEntity`).

## 13. CENTRALIZED SECURITY ARCHITECTURE (`core:security`)

Enforce defense-in-depth across the entire application:

- **6 Granular Permission Domains** (independently toggleable & auditable in Settings):
  1. `READ_ACCESS` (local files, memory, screen context)
  2. `WRITE_ACCESS` (AI workspace, file creation/modification)
  3. `DEVICE_CONTROL` (apps, accessibility, notifications, settings)
  4. `CLOUD_STORAGE` (Google Drive & optional ecosystem connectors)
  5. `BACKGROUND_EXECUTION` (scheduled automations, background voice, sync)
  6. `FINANCIAL_AUTHORIZATION` (wallet viewing vs. explicit biometric-gated signing)
- **Cryptographic & Transport Hardening:** TLS 1.3 / HTTPS everywhere, certificate pinning where applicable, SQLCipher database encryption with Keystore-backed keys, EncryptedSharedPreferences/DataStore for session metadata, and `FLAG_SECURE` on sensitive views.
- **Zero External Authority:** No external website, email body, notification text, downloaded file, or QR payload can independently authorize or elevate an Aqua tool permission.
- **Privacy & Compliance:** Full user data export and one-tap local + cloud wipe functionality, plus comprehensive redacted audit logs (never log secrets, seed phrases, or bearer tokens).
